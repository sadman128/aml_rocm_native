=== SLIDE 3 ===
  - Problem Statement
  - Modern Deep NIDS achieve >95% accuracy on normal traffic, but collapse to ~30% under tiny, undetectable packet tweaks.
  - System Performance
  - Clean vs. Robust
  - 95%
  - CLEAN ACC
  - ~30%
  - ROBUST ACC
  - The Adversarial Evasion Mechanism
  - Attackers slightly alter flow timing and packet sizes.
  - Consequence: The AI is tricked into classifying dangerous attacks as normal benign traffic.
  - Gradient-Volatile Features
  - Fragile Features: Classifiers rely on weak traffic clues that attackers can easily disguise.
  - Transient Socket Shortcuts
  - Shortcut Cheating: Models memorize port numbers and IP addresses instead of learning real attack behavior.
  - Defensive Hardening Trade-Offs
  - Stale Defenses: Existing defenses train once on old attacks, making them helpless against adaptive, modern attackers.

=== SLIDE 6 ===
  - Literature Review
  - Three structural vulnerabilities identified across existing NIDS defenses.
  - 01
  - Perturbation Staleness
  - Offline Augment. [1]
  - MECHANISM
  - Defenses like Static Triad inject pre-computed static attack samples once before retraining.
  - VULNERABILITY
  - As neural weights evolve during training, the decision boundary shifts away from static samples, allowing dynamic adaptive attacks to easily evade the model (16%–20% evasion rate).
  - 02
  - Line-Rate Latency Barrier
  - Runtime Defense [3, 4]
  - MECHANISM
  - Complex runtime verifications like real-time SHAP gates (85–220 ms) [3] and graph batch buffering (>2.4 ms) [4] introduce heavy computational overhead.
  - VULNERABILITY
  - High-speed cloud switches operate on microsecond scales (<0.05 ms); multi-millisecond per-flow processing causes buffer overflow and packet drops.
  - 03
  - Shortcut Learning Bias
  - Feature Selection [1, 18]
  - MECHANISM
  - Conventional feature selection evaluates feature importance exclusively on benign, nominal traffic.
  - VULNERABILITY
  - Models retain ephemeral socket shortcuts (Src/Dst Port, IP) and gradient-volatile features that attackers trivially manipulate to bypass detection.

  - Sanitization

  - Result: 69 continuous features remain.

  - Partitioning
  - Train/Val/Test
  - Strict Partitioning
  - 80% Dev Set (5M flows) / 20% Test Set (1.2M flows) locked Day 0.
  - Dev split: 72% Train / 8% Val.
  - Parameters fitted strictly on 72% Train.

  - MI Screening
  - Shannon MI
  - Feature Selection
  - Mutual Information filters 69 down to top 40 candidates.
  - Accelerates Shapley computation by >60%.
  - 04

  - Balancing
  - Oversampling
  - Continuous-Only SMOTE applied strictly within D train (72% Train).
  - Balances minority attacks without interpolating discrete flags.

=== SLIDE 10 ===
  - Proposed Methodology : Two-Phase Dynamic Training
  - Curriculum training to mitigate static attack staleness.
  - Curriculum Optimization Rationale:
  - Why Two Phases? Attacking a brand-new model from day one ruins its learning. It must learn normal traffic patterns first before facing attacks.
  - PHASE 1
  - Representation Warmup (Epochs 1-10)
  - Phase 1 (Epochs 1–10): Train on normal traffic first so the model builds solid, accurate foundations.
  - Train exclusively on clean data using standard cross-entropy loss.
  - PHASE 2
  - Dynamic Online Training (Epochs 11-50)
  - Phase 2 (Epochs 11–50): Generate live, fresh attacks for every training batch to defeat evolving attacks without hurting normal accuracy.
  - Updates model parameters via a balanced joint objective.
  - Joint Objective:
  - Result: Mitigates static attack staleness while preserving benign representation anchors.
